# Isolated PostgreSQL integration matrix

Plan only; no harness, containers or databases are started. Use disposable local/CI PostgreSQL with synthetic data, not production, previews, platform branches copied from production, or provider accounts. Later authorization must specify image/version, extensions, ephemeral volumes, credentials, network limits and cleanup. Use role-separated migrator/admin/runtime connections; assert current_user, role flags, backend PID and grants without logging credentials. Pin transport dependency versions and test a separate Netlify sandbox only with further permission.

| Area | Scenarios | Required outcome |
| --- | --- | --- |
| Ownership | Ownerless organization, two owners, mismatched pointer, inactive owner, deleting owner/global user, final deferred COMMIT checks | Invalid states fail at COMMIT; immediate uniqueness rejects duplicate active owner; no partial changes |
| Provisioning | Successful bootstrap, failure after each insert, same-key concurrent bootstrap, ambiguous commit | All organization/member/policy/audit/result commit together or none; one organization per bootstrap key |
| Transfer | Concurrent transfers, transfer vs revocation, demote/promote order, stale version, inactive target | One accountable active owner; deterministic serialization/retry; stale authority denied |
| Membership | Duplicate member, invalid role/grant shape, employee monitoring grant, tenant-key reassignment, manager grant escalation | Database and operation constraints deny invalid writes; no delegation escalation |
| Tenant isolation | Every tenant table read/insert/update/delete with A context vs B IDs; swapped composite FK references; organization root; global user lookup | Generic denial/zero rows; no data leak or cross-tenant writes; FK and RLS both exercised |
| RLS | Missing/empty/malformed settings, USING vs WITH CHECK, integrity trigger visibility, bootstrap-only scope | Default deny, correct tenant writes, constraints inspect all required rows, no universal bypass |
| Context spoofing | Runtime sets arbitrary organization/actor settings then calls routines; direct SQL attempted | Direct table access denied; routines require current membership; document trusted-server actor assertion boundary rather than claiming unforgeable GUCs |
| Permissions | All 5 roles × all 12 management permissions; scoped managers; revoked/inactive member; same-org unauthorized operation | Owner allowed; admin/manager explicit allowlisted grants only; employee/contractor denied management |
| Audit | Direct insert forgery, UPDATE/DELETE/TRUNCATE, cascades, owner role execution, failed mutation | Runtime denied; append actor from trusted context; committed mutation has audit; failed mutation has no transactional event |
| Idempotency | Concurrent same/different hash, replay after revocation, crash before/after commit, expired key, cross-actor reuse | One authorized result, hash conflict fails, replay reauthorized, no partial pending record or duplicate business effect |
| Revocation | Barrier-controlled authorize-vs-revoke races, role reduction, stale SERIALIZABLE snapshot, global logout-vs-write | Deterministic commit ordering; after-revocation operation fails or retries and fails; no stale permission use |
| Session | Tampered/expired/revoked cookie, epoch change, provider disable event, concurrent refresh, family reuse, CSRF/origin mismatch | Fail closed; rotation/replay semantics verified; independent organization revocation |
| Role privileges | runtime CREATE/ALTER/GRANT/SET ROLE/RESET ROLE attempts; table ownership; PUBLIC functions; search-path hijacking | No privilege escalation, no inherited privileged role, no writable definer search path |
| Connection reuse | A then B then no-context on same backend; success/rollback/savepoint/failed BEGIN/cancel/failed COMMIT/reconnect | No context leakage; pinned backend during transaction; dirty connection discarded; bounded pool resources |
| Retry behavior | SQLSTATE 40001/40P01, bounded contention, transport timeout/unknown commit | Retry complete operation with reauthorization and same idempotency key; unknown commit reconciled before rerun |
| Migration/restore | Fresh apply, same checksums twice, drift, custom security objects, failed mid-migration, old app with new schema, restored revocations | Ledger and catalog agree, security manifest preserved, publication blocked on failure, recovery proof captured |
| Billing guardrails | Logical entry rebilling with new revision, swapped allocation entry/revision, finalized snapshot mutation | Reject duplicates/mismatches; preserve immutable history (future schema required) |

Use synchronized barriers and multiple physical connections rather than sleeps for races. Assert SQLSTATE and final committed state. Test privileges with actual runtime login, not an admin connection after SET ROLE. Include negative controls: intentionally absent RLS policy/grant causes expected test failure. Test both pg and serverless transport plus deployment pool topology in a separate permitted platform sandbox; local PostgreSQL alone cannot validate managed serverless behavior. Report results by environment, version, role and transport. No integration test is reported as passed in Sprint 0.1.
