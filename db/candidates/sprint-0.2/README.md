# Quarantined security baseline

This SQL is a fresh, forward-only security-kernel candidate in the separate `hv` schema. It is not an upgrade of the inert public Drizzle design. No deploy configuration references it. Do not copy it to a migration directory or apply it during this sprint.

The candidate implements only security operations. There are no business tables, endpoints, providers, SDK initialization or database connection side effects. Every table in this candidate has forced RLS, including global users and bootstrap keys. Existing inert business-table definitions require a later reviewed reconciliation/baseline; they must not be activated independently.

## Isolated verification contract

A separately authorized operator prepares a fresh local disposable PostgreSQL database named `hourvia_disposable_*`, synthetic data only, and applies this exact reviewed candidate with the actual `hv_migrator` login. Preparation/application is not performed by the test suite. Never use a Netlify preview branch, production database, copied customer data, or default platform credentials.

Required role topology: NOLOGIN `hv_schema` and `hv_operation`; restricted LOGIN `hv_runtime`; separate LOGIN `hv_migrator`. Neither runtime nor operation role may belong to any other role or possess administrative flags. Schema owner must be a member of operation owner to assign function ownership; migrator must be able to assume schema owner. The candidate blocks unsafe role flags, runtime membership and inherited database/public-schema CREATE. The operator must additionally inspect all database/schema/function grants, role inheritance, database CONNECT, default privileges and object ownership. No credentials appear in SQL or documentation. Role provisioning is intentionally an explicit administrative prerequisite, not weakened to match unknown Netlify capabilities.

Install `psql` in the isolated test runner. Supply dedicated migrator/runtime connection settings through secure environment injection using `HOURVIA_TEST_MIGRATOR_URL` and `HOURVIA_TEST_RUNTIME_URL`. Enable only with `HOURVIA_DISPOSABLE_PG_AUTHORIZED=YES_SYNTHETIC_DISPOSABLE`. The runner accepts loopback hosts only and passes connection information through child environment, never command arguments. It redacts all database exceptions. Without authorization all 18 tests skip. There is no fallback to Netlify connection variables. An enabled but incomplete configuration fails.

Run the existing test command in a serial dedicated runner. The suite relies on its ordered synthetic fixture and leaves committed synthetic data for inspection; the operator destroys the entire disposable target afterward. It does not drop objects, provision roles, apply SQL or clean another environment. Separate administrative preparation is required by the no-application restriction.

## Security contract and limits

Runtime gets schema USAGE and only four function EXECUTEs. It gets no tables, sequences, DDL or trigger/function privileges. Operation owner gets narrow table privileges including UPDATE columns needed for row locks. It cannot update audits or idempotency records. Schema-owner definer integrity/audit triggers have a separate always-visible policy so caller RLS cannot hide invalid owners. The schema owner/migrator remain privileged administrative trust boundaries. Definers use fixed `pg_catalog` search paths and qualified objects, with PUBLIC execution revoked; runtime cannot assume their roles.

Server-verified actor, organization selector and correlation are transaction-local settings. Settings are assertions by trusted server code, not authentication credentials. A compromised runtime SQL caller can assert another actor; the absent provider/session integration must prevent arbitrary caller SQL and validate principal/session before activation. Database epoch checks support global invalidation but do not implement session expiry or a provider. Bootstrap replay and tenant revocation replay check current authority under locks. Provisioning keys serialize on global user; tenant writes serialize user then organization then membership. Ownership transfer is denied universally in this candidate.

Automatic audit triggers couple successful core mutations to actor/correlation/transaction attribution. Missing attribution aborts the mutation; audit insert errors roll back the entire transaction. Audits and idempotency records reject UPDATE/DELETE/TRUNCATE even for ordinary schema-owner DML. A DBA able to disable triggers or change policies remains outside this protection. Durable keys have no cleanup/expiry; retention is not silently selected. Monitoring stays OFF with no configuration operation; future admin/delegated monitoring configuration requires separate review.

Bootstrap stores organization outcomes; tenant revoke keys store actor/operation/key/hash/target with composite membership FK. Payload hashes must be computed from canonical, versioned server payloads. Replays require fresh authorization. Unknown COMMIT discards the connection and raises an explicit uncertain-outcome error; bootstrap lookup reconciles without performing a mutation. Null lookup is unresolved, never permission to immediately rerun. Tenant revocation reconciliation currently requires repeating its idempotent allowlisted operation after fresh authorization; no general-purpose mutation retry is exposed. No nontransactional external effects are permitted in transaction callbacks.

The integration tests exercise real statements using actual runtime credentials; no mocks provide database proof. Concurrent revocation uses two psql connections and asserts one committed version change, but deterministic barrier-controlled stale-authority races, transport faults, cancellation, unknown-COMMIT reconciliation, pooled reuse across actor A/B, savepoints, RLS negative controls and every future business table remain additional verification work. The same-connection test verifies local-setting reset, not Netlify pool reuse. Unit tests exercise lifecycle failure handling only.

## Promotion and recovery

Remain BLOCKED until real isolated SQL/PLpgSQL execution, role catalog review, broader race/fault matrix and Netlify-specific role/transport compatibility pass. Record PostgreSQL version, role/grant catalog and exact checksum. Reconcile this security schema with `db/schema.ts` and generator snapshots before any promotion; never generate business tables lacking policies/operations. Verify auto-generation suppression, immutable migration ledger, backup/PITR and isolated restore with approved RPO/RTO. Only a separate explicit authorization can place reviewed files in deploy-consumed directories. Any defect in an applied artifact receives a new forward repair; do not edit applied history. A failed candidate apply must roll back; an uncertain migration outcome requires catalog/ledger reconciliation. Code rollback does not undo schema changes. Restore must reconcile audits, idempotency and revocations before reopening writes.
