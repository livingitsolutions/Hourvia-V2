This candidate supersedes the never-applied Sprint 0.2 baseline for future isolated verification. It is a complete replacement fresh baseline, not a migration to apply after the old baseline. The old SQL remains byte-for-byte historical evidence. Apply neither during this sprint; never apply both to a target. No Drizzle configuration, deployment migration directory, client initialization, provider or endpoint references this SQL. Existing `db/schema.ts` stays inert and unreconciled. Every role/provisioning/Netlify prerequisite and promotion/recovery gate from the earlier candidate README remains applicable. Only a separately authorized operator may provision named roles, prepare a new local synthetic `hourvia_disposable_*` database and apply this exact revised checksum. ## Canonical authorization

Every operation requires transaction-local `hv.actor`, `hv.organization`, `hv.correlation`, `hv.operation` and `hv.epoch`. UUIDs use canonical hyphenated syntax (case-insensitive). Scope is exactly provision/revoke/read/lookup; epoch is canonical positive decimal up to the JavaScript safe-integer limit. Actor/session/epoch come only from server validation. Organization is a validated selector; database membership remains authoritative. These settings are assertions by trusted server code, not unforgeable authentication credentials. No provider or session implementation is activated.

Application TransactionAuthorization validation and SET LOCAL-equivalent parameterized set_config agree with database context_valid/require_context and operation policies. Context validation covers all settings even on reads and replay. Exact function scope and epoch argument must agree with transaction assertions. Audit accepts only provision/revoke scope. All core RLS policies require a valid canonical context; administrative integrity policies retain their explicit privileged visibility. Bootstrap reconciliation requires the original requested organization and lookup scope and never rewrites context to another tenant. After uncertain COMMIT retain original actor/organization/key/hash; a missing lookup remains unresolved and does not grant permission to rerun.

## Idempotency

Keys/digests must be non-null and valid before any lookup; comparisons use IS DISTINCT FROM. Bootstrap stores and compares requested organization/member identity as well as digest. Tenant revoke compares target and digest. Replay is durable and reauthorized; records remain append-only without TTL. Canonical server hashing includes a versioned operation envelope and supplied immutable request identity/payload; server callers must include org/member/target identity and never accept browser hashes or secrets. No general-purpose browser data endpoint exists.

## Transaction completion

Injected transport must expose PostgreSQL command tags. Only COMMIT acknowledges success. ROLLBACK tag is explicit aborted completion; missing/unexpected tags or connection failures are uncertain and discard the client without automatic retry. Known constraint rejection rolls back; 40001/40P01 retries are bounded and revalidate sessions. ROLLBACK cleanup must itself be acknowledged or the client is discarded. Callbacks receive an expiring operation handle that admits only the exact SQL for the asserted scope; it rejects transaction control and other operations. Callbacks remain trusted internal code: await every query, do not catch-and-ignore SQL errors, and do not perform external side effects. Runtime result handling must be verified against the exact Netlify peer/transport before activation.

## Integration runner

Set dedicated migrator/runtime settings via secure environment injection only and authorize with `HOURVIA_DISPOSABLE_PG_AUTHORIZED=YES_SYNTHETIC_DISPOSABLE`. Without it all 18 integration cases skip. Credentials must name distinct users at the same loopback host/port/database; protocol and database-name guards reject routing query options. Runner passes credentials through PGDATABASE environment, never argv, and does not inherit PGHOST/PGSERVICE/PGOPTIONS or other runner credentials. It uses psql without user initialization or prompts, with bounded connection/process timeouts. Loopback is not proof of isolation: the operator must exclude proxies/tunnels and verify no customer data.

A successful beforeAll checks actual migrator/runtime names, table inventory and committed fixtures for two organizations. Negative operations are separate from fixture creation. SQLSTATE-only psql diagnostics become sanitized typed statement errors; missing executable, timeout, malformed credentials, connection/authentication failures or wrong SQLSTATE cannot satisfy a denial test. All 18 cases have specific SQLSTATE assertions or successful post-state checks; deferred ownerless commit allows only the documented 23503/23514 constraint order. NULL request combinations, scope/epoch mismatch, all context fields and existing cross-tenant resources are included.

Cases 11/12 use concurrent physical psql connections but still lack deterministic revocation barriers. Direct commands use default isolation, not the SERIALIZABLE wrapper. Context reset is same-backend psql, not actual Netlify pooled reuse. Driver cancellation/failure injection, every policy USING/WITH CHECK negative control, transport pinning and full session races remain required further verification. SQLSTATE helper behavior must be validated with installed psql on the isolated runner. Tests preserve synthetic data; operator destroys the dedicated target after inspection. They do not apply SQL, deploy or connect to Netlify.
